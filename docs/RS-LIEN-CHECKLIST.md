## 0. საფუძვლები

- [ ] **ვინ აგზავნის:** RS (შემოსავლების სამსახური). dev-ზე RS-ის როლს სიმულატორი ასრულებს, ჩვენ მას `X-RS-Simulator-Token`-ით ვიძახებთ (ტოკენი ნიკამ უნდა მოგვცეს).
- [ ] **ვის ეხება:** RS ბრძანებას **ident-ზე** აგზავნის (`personId`), კონკრეტულ კლიენტზე არა. სისტემა თვითონ პოულობს ამ ident-ის ყველა wallet-ს: hub კლიენტებს და merchant-ს.
- [ ] **წინაპირობა:** ident-ს უნდა ჰქონდეს RS რეგისტრაცია და მიბმული WALLET კლიენტი.
- [ ] **მთავარი ფორმულა:** `Available = ბალანსი − Held`.
  - გასავალი ოპერაცია (გატანა, refund, debit) მხოლოდ Available-ს იღებს.
  - შემოსავალი (ჩარიცხვა) **არასდროს** იბლოკება.
- [ ] **სად ჩანს:**
  - ბიზნესის გვერდზე, ბლოკში "Liens & collections";
  - `GET /api/v1/rs/restrictions?rsNumber=…`;
  - hub კლიენტზე `balances[].held`.
- [ ] **სიმულატორის პასუხი ყოველთვის HTTP 200-ია.** შედეგი ჩანს `items[].code`-ში: `null` = მიღებულია, რიცხვი = უარი.
  - `1` — ident ვერ მოიძებნა;
  - `13` — ღია ანგარიში არ აქვს;
  - `21` — ყადაღის ნომერი უკვე არსებობს;
  - `11` — ინკასოს ნომერი უკვე არსებობს;
  - `24` — არასწორი სახაზინო კოდი.

### სტატუსები
- [ ] `PENDING` — მიღებულია, ჯერ არაფერი დაბლოკილა
- [ ] `PARTIALLY_RESTRICTED` — დაბლოკილია ნაწილი (ფული არ ჰყოფნის)
- [ ] `FULLY_RESTRICTED` — დაბლოკილია მთლიანი თანხა
- [ ] `PROCESSING` — ინკასო: RS-ს თანხა ვკითხეთ, გადახდა მიმდინარეობს
- [ ] `PARTIALLY_EXECUTED` / `EXECUTED` — ინკასო: ნაწილობრივ / სრულად გადაირიცხა სახაზინოში
- [ ] `WITHDRAWN` — RS-მა მოხსნა
- [ ] `REPLACED` — შესწორებამ ჩაანაცვლა
- [ ] `RETURNED` — ჩვენ დავუბრუნეთ RS-ს
- [ ] `FAILED` — გადარიცხვა 4-ჯერ ჩავარდა, ფული დაბლოკილი რჩება

## 1. ყადაღა (Lien) — მხოლოდ **ყინავს**, ფული არსად მიდის

**Flow:** RS აგზავნის ყადაღას → ფული wallet-ზე იყინება → თუ ფული არ ჰყოფნის, ახალი ჩარიცხვები hold-ს ავსებს → RS ყადაღას ხსნის → ყველაფერი თავისუფლდება.

- [ ] **HLD-01 / HLD-10 — ყადაღა ერთ wallet-ზე** ⭐
  - 📋 ბალანსი 100, ყადაღა 70 → held 70, available 30.
  - 📋 debit 40 → უარი (1141). debit 30 → გადის, ბალანსი 70.
  - 💡 დაბლოკილი 70 "სახელმწიფოსია", ამიტომ კლიენტს მხოლოდ 30-ის გამოყენება შეუძლია.
  - ✅ ვამოწმებთ: ბალანსი held-ზე დაბლა **ვერასდროს** ჩადის.

- [ ] **HLD-02 — ყადაღა ფულზე მეტია**
  - 📋 ident-ს აქვს 1100 (merchant 100 + hub 1000), ყადაღა 2000-ზეა.
  - 📋 იბლოკება ყველაფერი რაც აქვს (1100), სტატუსი `PARTIALLY_RESTRICTED`, მიზეზი "900.00 GEL short".
  - 💡 ვბლოკავთ იმას, რაც არის, დანარჩენ 900-ს მომავალი ჩარიცხვებიდან ველოდებით.
  - ✅ ვამოწმებთ: restrictedAmount 1100, held = ბალანსი, available 0.

- [ ] **HLD-03 — ახალი ფული ავსებს hold-ს (fill-up)**
  - 📋 HLD-02-ის მდგომარეობიდან შემოდის 500 → held მაშინვე +500 (restricted 1600).
  - 💡 სანამ ვალი სრულად არ დაიფარება, ყველა ახალი შემოსავალი იბლოკება.
  - ✅ ვამოწმებთ: held იზრდება, ისტორიაში ჩანს `RS_HOLD`.

- [ ] **HLD-04 — რომელი wallet ბლოკავს**
  - 📋 ყადაღა 500, merchant-ს აქვს 100, hub-ს 1000 → იბლოკება **მხოლოდ hub** (ყველაზე დიდი ბალანსი პირველი).
  - 📋 თუ ბალანსები თანაბარია → ბლოკავს ის, ვისაც `allocationPriority` უფრო დაბალი აქვს (payment 10 < hub 20).
  - 💡 რაც შეიძლება ნაკლებ ანგარიშს შევეხოთ.

- [ ] **HLD-05 — მხოლოდ GEL ითვლება**
  - 📋 კლიენტს მხოლოდ USD აქვს → არაფერი იბლოკება (held 0).
  - 💡 ვალი ლარშია, ვალუტის კონვერტაციის წესი ჯერ არ არსებობს. ⚠️ Jira-ში სხვანაირად წერია, ნიკასთან დასაზუსტებელია.

- [ ] **HLD-06 — wallet-ები, რომლებიც ვერ ბლოკავენ**
  - 📋 unlimited hub კლიენტი და instant settlement merchant → hold არ ედება (`holdCapable: false`).
  - 💡 unlimited ბალანსი რეალური ფული არ არის. instant settlement-ის დროს ფული ბალანსზე არ ჩერდება.

- [ ] **HLD-07 — ყადაღის მოხსნა**
  - 📋 RS ხსნის (`obtain-lien`) → `WITHDRAWN`, held 0, მთელი ბალანსი ხელმისაწვდომია.
  - ✅ ვამოწმებთ: allocations `RELEASED`, ისტორიაში ჩანს `RS_RELEASE`.

- [ ] **HLD-08 — უცნობი ან დახურული კლიენტი**
  - 📋 ident ჩვენთან არ არსებობს → code 1, არაფერი ინახება.
  - 📋 ყველა ანგარიში დახურულია → code 13.
  - 💡 RS-მა უნდა იცოდეს, რომ ჩვენთან ფული არ არის, და სხვა ბანკს მიმართოს.

- [ ] **HLD-09 — დუბლიკატი**
  - 📋 იგივე ყადაღის ნომერი მეორედ → code 21.
  - 📋 იგივე შეტყობინების ხელახლა გაგზავნა (`resend`) → იგივე პასუხი, ახალი ყადაღა არ იქმნება.
  - 💡 ორმაგი ბლოკვა = კლიენტის ფულის უსამართლოდ გაყინვა.
  - ✅ ვამოწმებთ: ამ ნომრით არსებობს **ზუსტად ერთი** restriction.

- [ ] **HLD-11 — დეტალები და reallocate**
  - 📋 დეტალებში ჩანს რომელ wallet-ზე რამდენია დაბლოკილი (`allocations[]`) და ისტორია.
  - 📋 reallocate → hold-ების ხელახლა განაწილება.

- [ ] **HLD-12 — გატანა და ყადაღა ერთდროულად** (რთულად დასატესტია)
  - 📋 available ვერასდროს ჩავა 0-ზე დაბლა.

- [ ] **HLD-13 — wallet იხურება** (დეველოპერი სჭირდება)
  - 📋 merchant იშლება → მისი hold ავტომატურად გადადის იმავე ident-ის hub კლიენტზე.
  - 💡 ვალი რჩება, უბრალოდ სხვა ანგარიშზე გადადის.

## 2. ინკასო (Collection) — ჯერ **ყინავს**, მერე **სახაზინოში რიცხავს**

**Flow:**
1. RS აგზავნის ინკასოს → იბლოკება ყადაღასავით (`FULLY_RESTRICTED`).
2. სამუშაო დღეს, 15:00–16:45-ში, ვეკითხებით RS-ს "დღეს რამდენი გადავიხადოთ?" — ხელით (`request-amount`) ან ავტომატურად 16:15-ზე → `PROCESSING`.
3. RS პასუხობს თანხას → ეს თანხა დაბლოკილიდან სახაზინოში გადაირიცხება → `EXECUTED`.

💡 RS-ს თანხას გადახდის დღეს იმიტომ ვეკითხებით, რომ ვალი იცვლება (ჯარიმა ემატება ან კლიენტმა ნაწილი თვითონ გადაიხადა).

- [ ] **COL-01 — ინკასო ჯერ იბლოკება**
  - 📋 მოსვლისთანავე → `FULLY_RESTRICTED`.
  - 📋 16:45-ის შემდეგ მოსულ ინკასოს `effectiveBusinessDay` = მომდევნო სამუშაო დღე.
  - 💡 ჯერ ფულს "ვიჭერთ", რომ კლიენტმა ვერ გაიტანოს.

- [ ] **COL-02 — თანხის ხელით მოთხოვნის წესები**
  - 📋 15:00–16:45-ის გარეთ ან დასვენების დღეს → 409 / 7017.
  - 📋 იმავე დღეს მეორედ → 409 / 7018.
  - 📋 ინკასოზე, სადაც არაფერი დაბლოკილა → 409 / 7011.
  - 📋 სწორ დროს → `PROCESSING`.
  - 💡 დღეში ერთხელ, რომ ორმაგი ჩამოჭრა არ მოხდეს.

- [ ] **COL-03 — ავტომატური მოთხოვნა 16:15-ზე**
  - 📋 ორი ინკასოა (priority 1 და 2) → მოითხოვება **მხოლოდ** priority 1.

- [ ] **COL-04 — სრული გადახდა** ⭐
  - 📋 RS ადასტურებს სრულ 100-ს → გადაირიცხა სახაზინოში → `EXECUTED`, hold-ები იხსნება.
  - ✅ ვამოწმებთ: hub ისტორიაში ჩანს `RS_TRANSFER` −100.

- [ ] **COL-05 — ნაწილობრივი გადახდა**

- [ ] **COL-06 — RS პასუხობს 0**
  - 📋 "დღეს არაფერი" → `NO_AMOUNT`, უკან `FULLY_RESTRICTED`, held 100 რჩება.
